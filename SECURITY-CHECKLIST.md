# SECURITY CHECKLIST

Scope: this is a **training build**. A local verified build proves the development
workflow. It does not approve this application for production telecom workloads.

## Data handling

- [x] Synthetic data only — every record is generated by `lib/data/generate.ts`
      from a fixed seed
- [x] No real MSISDNs, customer names, or national IDs
- [x] No payment information
- [x] No CDRs
- [x] No private network addresses or internal hostnames
- [x] No VPN or production credentials
- [x] No production database exports
- [x] Customer IDs are synthetic (`LTT-1xxxxx`), not real account numbers

## Secrets

- [x] No credentials committed
- [x] `.env*` is gitignored (scaffold default, verified)
- [x] `.env.example` contains variable names only, no values
- [x] No secret appears in source
- [x] No server secret is exposed through a `NEXT_PUBLIC_` variable
- [x] The SQLite database file is gitignored (`/data/*.db`)

## Input validation

- [x] Every query parameter validated server-side against an allowlist
      (`lib/validation.ts`)
- [x] Sort keys come from a fixed allowlist — an arbitrary column name is rejected
- [x] Report names come from a fixed allowlist
- [x] Pagination values are parsed as integers and clamped
- [x] Invalid input returns HTTP 400 with a useful message
- [x] Unknown customer ID returns HTTP 404
- [x] Frontend controls are never trusted as the validation layer

## Injection

- [x] All SQL uses bound parameters (`?`), never string interpolation
- [x] Allowlisted identifiers are the only values ever placed into SQL text
- [x] No dynamic `eval`, `Function`, or shell execution anywhere

## Information leakage

- [x] Error responses contain a message only — no stack trace, SQL, or file path
- [x] No sensitive data written to logs
- [x] Source maps not served in a production build

## Not implemented in V1 (deliberate, recorded)

These are genuine gaps, not oversights. They are out of V1 scope per
PROJECT-SCOPE.md and must be closed before any real deployment.

- [ ] Authentication — every route is currently public
- [ ] Authorization — no roles; any caller can read every subscriber record
- [ ] Rate limiting — no request throttling on any route
- [ ] Audit logging — reads of subscriber records are not logged
- [ ] Database row-level security — not applicable to local SQLite; required when
      moving to Supabase PostgreSQL
- [ ] Transport security — local HTTP only
- [ ] Dependency scanning in CI — `npm audit` reported 0 vulnerabilities at
      install time, but no automated recurring scan is configured

## Before production

Everything above under "Not implemented" must be closed, plus: approved LTT
infrastructure and identity provider, data classification review, access control,
audit logging, backups, monitoring, change management, penetration testing, and
an incident response owner.
